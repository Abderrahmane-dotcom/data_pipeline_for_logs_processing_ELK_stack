# ELK Stack Log Processing Simulation

A simulation project that reads historical build logs from files and processes them through the ELK pipeline to demonstrate real-time log processing, parsing, and analysis.

## What It Does

`
Historical Build Logs (logs_data/)
        
   simulate.py (reads & simulates real-time processing with delays)
        
   Filebeat (ships line by line to Logstash)
        
   Logstash (parses headers, extracts metrics, detects errors)
        
   Elasticsearch (indexes everything)
        
   Kibana (visualize & analyze)
`

## Quick Start

**1. Start services:**
\\\ash
docker-compose up -d
\\\

**2. Run the simulator (in another terminal):**
\\\ash
python simulate.py
\\\

**3. Open Kibana:**
Visit http://localhost:5601

**4. Create index pattern:**
- Stack Management  Index Patterns  Create
- Pattern name: \	est_devoir_2_logs\
- Time field: \@timestamp\

**5. Explore logs:**
- Go to Discover and watch logs appear in real-time

## How the Simulation Works

### simulate.py
- Reads static build log files from \logs_data/OneDrive_1_21-10-2025/log-*/\
- Writes them line-by-line to \logs/\ directory
- Adds 0.08s delay between lines to simulate real-time
- Stops when all files are processed

### Filebeat
- Watches the \logs/\ directory
- Detects new lines as they're written
- Ships them to Logstash via beats protocol (port 5044)

### Logstash
- Receives events from Filebeat
- **Extracts** header fields: builder, slave, buildid, revision, etc.
- **Parses** metrics: exit_code, elapsed_time, result_status
- **Detects** errors (is_error field)
- **Removes** noise (empty lines, separators)

### Elasticsearch
- Stores all events in index \	est_devoir_2_logs\
- Converts Unix timestamps to searchable dates

### Kibana
- Visualizes the processed logs
- Allows filtering and analysis

## Extracted Fields

| Field | Type | Description |
|-------|------|-------------|
| \uilder\ | text | Builder identifier |
| \slave\ | text | Slave machine |
| \uildid\ | text | Build identifier |
| \
evision\ | text | Git/VCS revision |
| \exit_code\ | integer | Program exit code |
| \elapsed_time\ | float | Build time in seconds |
| \

| \is_error\ | boolean | Error flag (true if failed) |

## Common Commands

\\\ash
# Check all services running
docker-compose ps

# View Logstash processing logs
docker-compose logs logstash

# Search for errors
curl "http://localhost:9200/test_devoir_2_logs/_search?q=is_error:true"

# Stop everything (keeps data)
docker-compose stop

# Full restart (removes data)
docker-compose down -v && docker-compose up -d
\\\

## Adjusting Simulation Speed

Edit \simulate.py\:
\\\python
DELAY_BETWEEN_LINES = 0.08  # Default (80ms between lines)
DELAY_BETWEEN_LINES = 0.01  # Faster (10ms)
DELAY_BETWEEN_LINES = 1.0   # Slower (1 second)
\\\


## Notes

- This is a **simulation/demo** project - it processes static files, not live logs
- The simulator runs once and stops when logs_data/ is fully processed
- All extracted data is stored in Elasticsearch for long-term analysis
- Kibana provides visualization and interactive analysis of the processed logs
